The frontend and Agent run in separate Windows processes and communicate over named pipes. Managed builds use separate executables. Native AOT links the Agent into PasswordManagerLocal.exe and runs it in a separate process with --agent. The project-reference graph shows the default build.

Android is shown separately because its runtime architecture differs from Windows. The Android manifest declares a non-exported foreground Service and does not assign it a separate android:process, so the Activity and Service live in the same application process. The service attachment is Android Binder/service communication inside that process; there is no Windows named-pipe IPC path here.
